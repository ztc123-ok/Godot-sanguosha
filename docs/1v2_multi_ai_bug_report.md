# 序章第二战 1v2 多 AI 场景综合测试 Bug 报告

**测试报告生成时间：** 2026-08-04
**测试环境：** Godot 4.6 Headless 模式
**测试输入：** `PrologueMultiEnemySmokeTest.tscn --fuzz`

在针对您最新添加的“序章第二战 1v2 多 AI”场景进行了深度冒烟测试后，我发现当前的底层代码依然遗留了大量 1v1 时代的硬编码和流程假设。虽然您已经引入了 `enemies` 数组并对 `other_player` 做了 `_default_rival(player)` 的兜底，但由于《三国杀》涉及复杂的多目标选择、AOE 遍历和延时结算，这套兜底方案在实际运作时引发了全面的状态机崩溃。

以下是本次测试捕获的核心缺陷汇总（所有 Bug 均严谨参照原版三国杀规则得出）：

---

## 1. 胜负判定与生命周期 Bug (Critical)
> [!WARNING]
> 系统无法正确识别 1v2 模式下的结束条件。

- **全部反贼阵亡后未判定胜利**：测试用例杀死两名 AI 后，游戏未能触发胜利（未能发出 `battle_finished(true)`），这表明现有的 `match_finished` 判定逻辑可能依然在检查 `enemy.hp <= 0` 这种单例变量，而不是检查 `living_enemies().is_empty()`。
- **玩家阵亡未正确重启对局**：当玩家阵亡时，测试捕捉到系统抛出“玩家阵亡后自动重开对局”以及“重开后玩家满体力先手”断言失败。重开流程未能完整清理或初始化 1v2 结构。

## 2. 目标选择机制失效 (High)
> [!CAUTION]
> 凡是需要“手动或半自动指定除默认对手以外的目标”的技能与锦囊，全部出现流程挂起或指派失败。

- **【过河拆桥】与【顺手牵羊】指定目标失败**：在 1v2 中，玩家应当能够自由选择 AI1 或 AI2。但目前测试报告指出：“过河拆桥可指定 AI1”、“顺手牵羊可指定 AI2”断言失败。这暗示当前 `GameManager` 的锦囊使用入口仍默认把目标锁死为 `other_player(player)`，缺少了“等待玩家选择存活目标”的 UI Flow。
- **【丈八蛇矛】失去目标选择**：原版丈八蛇矛两张牌当【杀】时，在多人局应进入 `SELECTING_TARGET`。但测试报告“丈八蛇矛多人局等待选择目标”失败，说明虚拟杀的生成仍然被强制分配给了唯一的 `_default_rival`。

## 3. AOE 轮转结算逻辑断裂 (High)
> [!IMPORTANT]
> 范围伤害锦囊无法正确贯穿多名角色。

- **【南蛮入侵】与【万箭齐发】链条断裂**：在“南蛮先结算 AI1 并使其阵亡”以及“南蛮继续结算 AI2”的连贯测试中报错。这暴露出当前系统对 AOE 的处理是单向单目标，或者在循环迭代中（例如 AI1 阵亡引发 `die` 结算）改变了数组结构或提前改变了 `flow_state`，导致针对 AI2 的结算被直接跳过或吞没。

## 4. 复杂双目标技能全盘崩溃 (Critical)
> [!WARNING]
> 【反间】、【离间】、【借刀杀人】这三种《三国杀》最经典的多目标交互逻辑，在当前状态机下表现为 100% 失败率。

- **【离间】(貂蝉)**：
  - 测试断言“离间第一步选择决斗使用者”与“第二步选择决斗对象”均失败。
  - **原因**：离间需要连续两次指定不同的男性目标（AI1 和 AI2），当前架构仅支持单次 `request_target`，二次目标收集直接导致流程锁死。
- **【反间】(周瑜)**：
  - 断言“反间选完 AI2 后进入选花色”失败。
  - **原因**：针对特定 AI 释放反间后，目标必须回调进入 `SKILL_CHOOSE_SUIT`（选花色），由于目标体系混乱，UI 和网络层无法正确把选花色权限移交给 AI2。
- **【借刀杀人】**：
  - “指定 AI2 后进入借刀响应”、“AI1 按指定对 AI2 出杀并造成伤害”均失败。
  - **原因**：借刀杀人要求：1. 使用者选择目标A（有武器的人）。2. 提示A选择目标B（要求距离合法）。当前代码完全缺乏传递次级目标的载体（上下文 `SkillUseContext` 仅有单一 `target`）。

---

### 📝 测试结论总结

您引入 `active_battle = 2` 后，1v2 的**视图容器**（两套手牌、体力条）应该是成功创建了，但核心的**事件循环（Event Loop）与目标上下文（Targeting Context）**尚未匹配。

目前的 `GameManager` 设计高度依附于“A 打 B”的单行道。为了真正支撑起 1v2 甚至多人群战，建议接下来的开发重心放在：
1. **统一 Target Selection 阶段**：淘汰 `other_player` 的兜底，所有出牌必须通过通用的 `SELECTING_TARGET` 收集目标数组。
2. **重构 AOE / 借刀结算栈**：支持子结算队列（例如 South Barbarian Invasion 入栈后，分别将 AI1、AI2 的打出杀响应独立入栈）。
3. **修复胜负检查机制**：将生命周期结束检测替换为集合级别的检查（当 `players` 或 `living_enemies` 任意一方为空时判定）。
