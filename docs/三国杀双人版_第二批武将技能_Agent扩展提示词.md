# 《三国杀》双人版第二批武将技能 Agent 扩展提示词

> 前置基线：先完整阅读 `docs/三国杀双人版_角色技能功能_Agent提示词.md`。  
> 本文件不是从零生成提示词，只用于在第一批 9 名武将已经实现并通过测试后，增量扩展第二批 9 名标准版武将。

## 扩展范围

- 保留第一批：曹操、张辽、许褚、关羽、张飞、赵云、甘宁、孙权、吕布。
- 新增第二批：司马懿、夏侯惇、郭嘉、甄姬、刘备、诸葛亮、吕蒙、黄盖、周瑜。
- 完成后共 18 名可选武将。
- 使用标准版（旧标）技能，不混入界限突破、国战或 1V1 专属技能。
- 本批不实现主公技、限定技、觉醒技、使命技、转换技，也不为这些类型创建占位枚举和空流程。

一、必须保持的架构边界

1. 兼容 Godot 4.6 stable；禁止 Godot 3.x 语法、废弃 API、第三方插件和伪代码。
2. Main 只绑定 GameManager 与 UIManager。
3. GameManager 仍是阶段、判定、牌移动、技能触发、伤害、失去体力、濒死、胜负和 AI 的唯一规则入口。
4. BattlePlayer 只保存武将、技能、体力、手牌、装备、判定区和回合标记，不直接推进流程。
5. Skill 脚本声明发动条件、规则修正和结构化结算请求，不直接修改手牌、体力、牌堆、装备或 FlowState。
6. UIManager 只订阅状态并提交 request/can_* 请求；玩家和 AI 共用同一合法性与结算入口。
7. 第一批已有的 `ActivationMode.ACTIVE/TRIGGERED/VIEW_AS/MODIFIER`、`SkillTag.LOCKED`、`UsageScope.UNLIMITED/PER_TURN` 继续使用，不新增本批没有使用的技能类型。
8. 处理区、实体牌、虚拟牌、DamageContext、continuation、skill_owner/skill_actor 和 generation 规则继续沿用第一批设计。
9. 每次技能询问、发动、放弃、代价、改判、牌移动、伤害和返回状态均同时写入控制台与界面对局日志。

二、本批需要补充的通用能力

只能在现有框架不足时增加以下通用能力，禁止按武将名在 GameManager 堆积巨大 if/match：

1. JudgementContext：记录判定原因、判定角色、原判定牌、当前生效牌、改判者、被替换牌和最终去向。
2. 统一判定管线：翻出原判定牌 → 【鬼才】改判窗口 → 最终判定牌生效 → 【天妒】等生效后触发 → 判定牌进入获得者、手牌或弃牌堆。
3. TriggerQueue：按明确时机串行保存待结算的可选技/锁定技和 continuation，禁止用同步递归嵌套伤害、判定和技能。
4. 私有临时牌区：支持【遗计】【观星】。只有实际操作者是人类玩家时才显示牌面；AI 的私有信息不得泄露给玩家。
5. 统一失去体力入口：失去体力仍检查濒死/死亡，但不创建 DamageContext，不触发受到伤害类技能，也不传播铁索伤害。
6. 有效牌行为记录：记录在当前角色出牌阶段内真正使用/打出的有效牌类型，实体牌和视为牌统一记账，非法请求和取消不记账。

按需要新增或扩展 FlowState，至少能清楚表达：

- JUDGEMENT_REPLACE：鬼才改判；
- DECK_REORDER：观星置顶、置底和排序；
- SKILL_ASSIGN_CARDS：遗计逐张分配；
- CHOOSING_SUIT：反间选择花色；
- 现有 SKILL_CONFIRM、SKILL_SELECT_CARDS、SKILL_SELECT_TARGET、SKILL_RESOLVING 继续复用。

每个状态必须保存实际操作者、合法选项、已选内容、成功/取消/无合法选项分支以及返回 continuation。不能只用 `current_player().is_ai` 判断权限。

三、第二批 9 名标准版武将

每个技能使用独立脚本，在 GeneralFactory 和 SkillFactory 注册，并标注技能名称、类型、规则说明及当前可用状态。

1. 司马懿，魏，3 体力

   反馈（触发技，`TRIGGERED + UNLIMITED`）：
   - 每次受到一次伤害后，若伤害来源的手牌区、装备区或判定区至少有一张牌，可以选择获得来源的一张牌。
   - 装备区和判定区为明牌，可选择具体实体牌；选择暗置手牌区时随机获得一张，不得查看其余手牌。
   - 伤害没有来源、来源已没有牌或牌已被其他 continuation 移走时，安全跳过，不得复制牌。

   鬼才（触发技，`TRIGGERED + UNLIMITED`）：
   - 任意角色的判定牌生效前，可以打出一张手牌代替之。
   - 被替换的原判定牌进入弃牌堆，新牌成为 JudgementContext 的唯一最终判定牌。
   - 后续花色、点数、颜色、天妒、洛神和判定结果只读取最终判定牌。
   - 同一判定中每名司马懿至多获得一次改判机会，不能因自己改判而无限重新询问。

   AI：反馈默认发动；鬼才仅在能改善自己的判定或恶化对手判定时发动。

2. 夏侯惇，魏，4 体力

   刚烈（触发技，`TRIGGERED + UNLIMITED`）：
   - 每次受到一次伤害后，可以判定。
   - 若最终判定结果为红桃，无后续效果。
   - 若不为红桃，伤害来源选择：弃置两张手牌，或受到夏侯惇造成的 1 点普通伤害。
   - 来源不足两张手牌时不能选择弃牌，只能受到伤害；来源不存在或已死亡时不再产生惩罚。
   - 刚烈伤害必须经过统一 DamageContext、濒死和死亡流程，并能触发受伤者的合法技能；结算结束后继续原伤害链。

   AI：夏侯惇在来源存在时发动；作为来源时根据体力、手牌价值和自救能力选择合法分支。

3. 郭嘉，魏，3 体力

   天妒（触发技，`TRIGGERED + UNLIMITED`）：
   - 自己的判定牌生效后、进入弃牌堆前，可以获得最终生效的判定牌。
   - 延时锦囊、八卦阵、刚烈、洛神等必须共用判定管线；同一实体判定牌只能移动一次。

   遗计（触发技，`TRIGGERED + UNLIMITED`）：
   - 每受到 1 点伤害后，可以观看牌堆顶两张牌，并将两张牌逐张交给自己或对手。
   - 两张可以交给同一角色，也可以分别交给双方。
   - 一次 N 点伤害生成 N 个依次结算的遗计触发，每次独立选择发动或放弃。
   - 两张牌先进入仅郭嘉可见的临时分配区；全部确认归属后再移动，取消和重复提交不得复制或丢失牌。

   AI：天妒、遗计默认发动；遗计优先把高价值牌交给自己，不主动资助敌方。

4. 甄姬，魏，3 体力

   倾国（视为技，`VIEW_AS + UNLIMITED`）：
   - 可以将一张黑色手牌当【闪】使用或打出；标准版倾国不能使用装备区牌。
   - 支持普通【杀】、【万箭齐发】和【无双】的多张【闪】响应；一次倾国只提供一张有效【闪】。

   洛神（触发技，`TRIGGERED + UNLIMITED`）：
   - 准备/开始阶段开始时，可以判定。
   - 最终生效牌为黑色时获得该牌，并可以再次进行洛神；为红色时将判定牌置入弃牌堆并结束流程。
   - 第一次判定前和每次黑色结果后均可继续或停止；停止不能额外翻牌。
   - 每次判定均允许鬼才介入，并以改判后的最终颜色结算。

   AI：有牌可判定时开始洛神并在黑色后继续；安全保护必须基于实际可用实体牌数量，不能用任意固定小次数改变规则或形成死循环。

5. 刘备，蜀，4 体力

   仁德（主动技，`ACTIVE + UNLIMITED`）：
   - 出牌阶段，可以将至少一张手牌交给对手；同一出牌阶段可以多次发动。
   - 记录本阶段通过仁德交出的累计牌数。累计第一次达到 2 张时，刘备尝试回复 1 点体力，本阶段仅结算一次。
   - 若达到 2 张时刘备满体力，本次回复虽然没有实际增加体力，回复机会仍已消耗，本阶段不能等受伤后再次回复。
   - 只能交出手牌，确认前可以取消且不移动牌；确认后直接进入目标手牌，不经过处理区或弃牌堆。
   - 双人版不实现主公技【激将】。

   AI：双人敌对模式下默认不把有用牌交给对手；无合理收益时直接放弃仁德并继续出牌流程，禁止反复空尝试。

6. 诸葛亮，蜀，3 体力

   观星（触发技，`TRIGGERED + UNLIMITED`）：
   - 准备/开始阶段开始时，可以观看牌堆顶两张牌。
   - 将任意数量以指定顺序放回牌堆顶，其余以指定顺序置于牌堆底，必须支持 0、1、2 张置顶。
   - 牌堆不足两张时先按原有规则用弃牌堆补充；确认前可调整顺序或取消，取消表示保持原顺序。
   - 人类诸葛亮可见牌面；AI 诸葛亮的观星牌面不得显示给玩家。AI 应结合随后的判定和摸牌阶段排序。

   空城（锁定技，`MODIFIER + LOCKED + UNLIMITED`）：
   - 没有手牌时，不能成为【杀】或【决斗】的合法目标。
   - 接入统一目标合法性检查，覆盖实体牌、虚拟牌、借刀产生的【杀】和技能产生的【决斗】。
   - 只限制【杀】和【决斗】，不限制南蛮入侵、万箭齐发、火攻或其他牌。
   - 目标已经合法确定后才失去最后一张手牌，不追溯取消已经建立的目标关系。

7. 吕蒙，吴，4 体力

   克己（触发技，`TRIGGERED + UNLIMITED`）：
   - 若吕蒙未在自己本回合的出牌阶段内使用或打出过有效类型为【杀】的牌，结束出牌阶段时可以跳过弃牌阶段。
   - 实体【杀】、武圣/龙胆等虚拟【杀】、丈八蛇矛响应以及在自己出牌阶段内因【决斗】打出的【杀】均计入。
   - 仅选择后取消、非法请求或没有真正提交的【杀】不计入。
   - 发动后直接进入结束阶段，不遗留 DISCARDING 状态，不重复结束阶段或切换回合。

   AI：手牌数超过上限且符合条件时发动，否则正常进入弃牌阶段。

8. 黄盖，吴，4 体力

   苦肉（主动技，`ACTIVE + UNLIMITED`）：
   - 出牌阶段，可以失去 1 点体力，然后摸两张牌；符合条件时同一阶段可以多次发动。
   - 失去体力不是受到伤害：没有伤害来源和伤害牌，不触发奸雄、反馈、刚烈、遗计、藤甲或铁索连环。
   - 失去体力后若进入濒死，先完成现有自救/死亡流程；成功脱离濒死后才继续摸两张，死亡或游戏结束则不摸牌。
   - continuation 不能提前回到出牌阶段、漏掉濒死或重复摸牌。

   AI：仅在体力大于 1，或能确定自救且收益合理时发动；每次 AI 行动循环至多发动一次，然后重新评估，禁止死循环。

9. 周瑜，吴，3 体力

   英姿（触发技，`TRIGGERED + UNLIMITED`）：
   - 摸牌阶段可以令本次正常摸牌数 +1。
   - 复用 DrawContext；不能直接额外调用一次摸牌而绕开摸牌阶段修正与日志。

   反间（主动技，`ACTIVE + PER_TURN`，`max_uses = 1`）：
   - 出牌阶段，若周瑜有手牌，可以令对手先选择黑桃、红桃、梅花、方块中的一种。
   - 对手随后随机获得周瑜的一张暗置手牌并展示；目标不能查看后再选牌。
   - 若获得牌的花色与所选花色不同，周瑜对其造成 1 点普通伤害；相同则不造成伤害。
   - 无论是否造成伤害，获得的牌都不退回。牌移动在伤害之前，伤害复用 DamageContext、濒死和触发队列。

   AI：英姿默认发动；处理反间时不得读取不可见牌面，选择花色后必须完成获得与伤害分支。

四、触发顺序与关键交互

1. 同一结算点出现多个技能时，先构造触发队列，再逐个询问/结算；每项结束后恢复队列，不用同步递归覆盖 pending_skill。
2. 判定牌只有一个最终实体去向：被鬼才替换的原牌弃置；最终牌由天妒/洛神获得或按判定规则进入弃牌堆，不能同时存在两个区域。
3. 遗计按“每受到 1 点伤害”产生触发；反馈和刚烈按“一次伤害事件结束后”各产生一次触发，不得混淆伤害点数与伤害次数。
4. 受到伤害技能必须在既有伤害、濒死、死亡规则允许的时机触发；角色死亡后不得继续弹出由其操作的可选技能。
5. 苦肉的失去体力与 DamageContext 完全分离，但共用濒死和死亡入口。
6. 视为牌和实体牌使用统一 `effective_card_type`；倾国响应无双时，每张黑牌只计一张闪。
7. 空城在建立目标时检查，不用 UI 隐藏代替规则层校验。
8. 第一批奸雄、无双、八卦阵、龙胆、丈八蛇矛等与第二批技能组合时，仍必须走同一规则入口。

五、选将与 UI

1. 在现有选将列表中新增 9 名武将，完成后共有 18 名；AI 仍从玩家未选择的武将中选择，测试可按 general_id 确定性指定。
2. 18 名武将卡片和长技能说明必须可滚动，不能撑出 1280×720。
3. 对局角色区显示新武将的势力、体力、技能类型、说明和本回合已用状态。
4. 鬼才显示判定原因、当前判定牌以及“改判/放弃”；洛神显示继续/停止和本轮获得数量。
5. 遗计显示两张临时牌及逐张归属；观星提供置顶、置底和顺序调整。AI 操作时只能显示过程提示，不能显示私有牌面。
6. 反馈选择明置区域或暗手牌区；反间先显示四种花色，随机牌获得后才公开。
7. 仁德支持多选、取消和确认；苦肉按钮必须防止连续点击绕过 SKILL_RESOLVING。
8. 所有按钮只调用 GameManager 的 request_skill_* 或既有公共请求，不直接修改领域状态。

六、AI

AI 必须与玩家共用技能入口，并能：

- 合理发动/放弃反馈、鬼才、刚烈、天妒、遗计和洛神；
- 在观星、遗计期间处理私有牌且不向玩家泄露；
- 使用倾国完成普通闪、AOE 和无双多张闪响应；
- 正确跳过或进入弃牌阶段；
- 有边界地使用苦肉，不因摸到桃或血量变化形成无限循环；
- 完成反间花色选择、随机获得、展示和伤害分支；
- 无合法牌、目标或选项时安全放弃并恢复 continuation；
- 所有延迟操作检查 generation、FlowState 和 skill_actor，重新开始/重新选将后旧回调失效。

七、强制自动化测试

不得删除、放宽或绕过现有：

- tests/RuleSmokeTest.tscn
- 第一批 tests/SkillSmokeTest.tscn

新增：

- tests/SecondBatchSkillSmokeTest.gd
- tests/SecondBatchSkillSmokeTest.tscn

测试必须使用确定性牌堆、花色、点数、手牌和武将，不依赖随机结果。至少覆盖：

1. GeneralFactory 共创建 18 名武将，id 唯一，第二批技能脚本、体力和分类正确；没有新增未使用的技能类型。
2. 第一批 9 名武将仍可创建、选中和运行，原测试结果不变。
3. 反馈：合法区域获得、暗手牌不泄露、无来源/无牌跳过、实体牌只移动一次。
4. 鬼才：改判和放弃；原牌弃置；最终花色/点数驱动后续判定；同一角色不能无限改判。
5. 刚烈：红桃无效果；非红桃弃两手牌或受伤；不足两牌强制受伤；反伤进入濒死并返回原伤害链。
6. 天妒：获得最终判定牌与放弃入弃牌堆；覆盖延时锦囊和八卦阵判定；与鬼才组合不复制牌。
7. 遗计：1 点伤害分配两张；2 点伤害触发两轮；同方/双方分配；取消与确认不丢牌、不复制。
8. 倾国：黑色手牌可当闪，红牌和黑色装备不可；覆盖万箭与无双逐张响应。
