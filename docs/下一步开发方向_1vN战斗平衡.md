# 下一步开发方向：单机 1vN 战斗平衡

## 1. 文档目的

本文档将 `GDD.md` 中的 1vN 设计原则拆解为下一阶段可执行的开发计划。目标是优先改善序章第二战的玩家压力，同时把相关能力建设成可复用于后续 1v3、精英战和 BOSS 战的关卡系统。

本阶段不追求一次完成完整 Roguelite 冒险、全部敌人意图或所有 BOSS 机制。交付重点是：**配置化战斗规则、可用的前后排距离、玩家敌众补偿、随从模板、击杀奖励，以及可验证的平衡数据。**

## 2. 当前问题判断

当前第二战主要通过 `enemy_count = 2` 将 1v1 扩展为 1v2。每名角色仍按标准武将体力、4 张起始手牌、独立回合和完整技能运行，玩家需要击杀全部敌人才获胜。

这会产生四项叠加压力：

1. **资源压力**：敌方每轮总摸牌量、手牌储备和装备获取能力接近玩家的两倍。
2. **行动压力**：玩家每轮要承受两个完整敌人回合，但通常仍只有一次标准摸牌和一次【杀】额度。
3. **技能压力**：随机生成的两个完整武将可能形成双控制、双爆发或强联动，波动远大于序章应有难度。
4. **距离失效**：三人环形座次中角色通常彼此距离均为 1，GDD 期望的前后排、武器范围和坐骑博弈没有真正形成。

因此本阶段不以“统一增加玩家若干体力”作为主要修复方案，而是先修正阵型与行动经济。

## 3. 版本目标与非目标

### 3.1 版本目标

- 序章第一战继续使用标准 1v1 教学规则。
- 序章第二战改为“玩家 vs 前排精英＋后排随从”。
- 关卡可配置阵位、初始体力修正、起手牌数量、摸牌修正、出【杀】额度、换牌和击杀奖励。
- 距离、武器、坐骑及武将距离技能在阵型中使用同一套合法性判断。
- 敌人减员后阵位、回合顺序和玩家补偿能够正确更新。
- UI 清楚展示前后排、当前可选目标、敌众补偿和战利品选择。
- 自动测试覆盖规则正确性，平衡日志能够支持真人测试分析。

### 3.2 本阶段非目标

- 不重做全部卡牌与技能框架。
- 不引入护甲值、暴击率、百分比减伤等新数值系统。
- 不为每个标准武将制作专属 PVE 版本。
- 不在第一轮实现复杂的 1v4、召唤物、可移动站位或完整 BOSS 多阶段流程。
- 不用降低 AI 合法性、随机跳过出牌或修改抽牌概率的方式伪造平衡。

## 4. 序章第二战首轮规则

以下参数为首轮可玩版本的测试基线，不是最终锁定数值：

```text
玩家：标准武将，最大及当前体力 +1
玩家起始手牌：4 张
开局换牌：最多选择 2 张洗回牌堆并等量重抽，仅一次

敌人 1：前排精英，4 体力，4 张起始手牌，完整或筛选后的技能
敌人 2：后排随从，2~3 体力，2 张起始手牌，至多 1 个简单公开技能

两名敌人存活时：
- 玩家摸牌阶段摸 3 张
- 玩家出牌阶段最多使用 2 次【杀】

首名敌人阵亡时：
- 玩家选择回复 1 点体力，或摸 2 张牌
- 若前排阵亡，后排前移

仅余一名敌人时：
- 玩家恢复标准摸牌数
- 玩家恢复由武将和装备决定的标准出【杀】次数
```

建议首轮固定或从白名单中抽取敌人组合，不直接从全部 25 名武将中完全随机抽取。随从优先使用无强控制、无爆发叠加、说明简单的模板。

## 5. 配置数据设计

### 5.1 扩展战斗配置

将现有仅包含 `enemy_count` 的关卡配置扩展为数据驱动结构。字段名称可根据现有代码规范调整，但职责应保持集中：

```gdscript
const BATTLE_CONFIGS := {
    1: {
        "enemy_count": 1,
        "formation": "DUEL",
        "player_max_hp_bonus": 0,
        "player_draw_bonus_per_extra_enemy": 0,
        "player_slash_limit_per_living_enemy": false,
        "opening_mulligan_count": 0,
        "kill_reward": "NONE",
        "enemies": [
            {"kind": "ELITE", "slot": "FRONT", "opening_hand": 4},
        ],
    },
    2: {
        "enemy_count": 2,
        "formation": "FRONT_REAR",
        "player_max_hp_bonus": 1,
        "player_draw_bonus_per_extra_enemy": 1,
        "player_slash_limit_per_living_enemy": true,
        "opening_mulligan_count": 2,
        "kill_reward": "HEAL_ONE_OR_DRAW_TWO",
        "enemies": [
            {"kind": "ELITE", "slot": "FRONT", "opening_hand": 4},
            {"kind": "MINION", "slot": "REAR", "max_hp": 3, "opening_hand": 2},
        ],
    },
}
```

### 5.2 配置读取原则

- `GameManager` 仍是规则结算唯一入口。
- 关卡差异只在初始化和明确的规则查询方法中读取，不把 `active_battle == 2` 分散到卡牌脚本、技能脚本和 UI 中。
- 提供统一查询方法，例如：
  - `current_battle_config()`
  - `draw_count_for(player)`
  - `slash_limit_for(player)`
  - `opening_hand_count_for(player)`
  - `formation_slot_of(player)`
  - `kill_reward_for(defeated)`
- 第一战和普通 1v1 测试在没有新字段时保持原行为。

## 6. 分阶段实施计划

### 阶段 A：建立基线与统计

先记录修改前的第二战真人与自动对局数据，避免只凭体感反复调参。

需要记录：

- 玩家/敌方阵容和各自技能。
- 胜负与总回合数。
- 首名敌人阵亡回合。
- 玩家每回合摸牌数、出【杀】次数和回合结束手牌数。
- 玩家受到的伤害按来源、卡牌和回合分类。
- 玩家没有合法进攻行动的回合数。
- 失败时两名敌人的剩余体力。
- 状态机救援、卡牌总数漂移和异常中止次数。

输出应区分“技术上正常结束”和“玩家获得胜利”，不能继续用对局完成率代替通关率。

### 阶段 B：配置化玩家补偿与敌人模板

1. 扩展 `BATTLE_CONFIGS`。
2. 将全员固定摸 4 张改为按角色配置起手牌数量。
3. 在摸牌计算入口应用“孤军”摸牌修正。
4. 在现有 `slash_use_limit()` 入口应用敌众修正，继续保留诸葛连弩和武将技能修正。
5. 开局应用玩家体力修正，但不得永久修改武将基础定义。
6. 增加随从模板，使随从拥有独立体力、手牌、阵位和公开技能字段。

这一阶段完成后，即使阵型 UI 尚未完成，也应能通过测试脚本验证数值与规则查询正确。

### 阶段 C：前后排与距离

1. 为参战角色增加明确的阵位数据，不再仅依赖存活角色数组下标推导 PVE 距离。
2. 实现玩家到前排基础距离 1、到后排基础距离 2。
3. 保留武器范围、±1 坐骑和武将技能对最终距离的修正。
4. 前排阵亡后，将首名存活后排移动至前排，并发出阵型变化事件。
5. AI 与玩家调用同一个 `distance_between()`、`can_slash_target()` 和锦囊目标校验入口。
6. 检查【顺手牵羊】、【兵粮寸断】、【借刀杀人】以及无距离限制技能在新阵型下的目标合法性。

阵位不应因为角色死亡后简单压缩数组而无提示改变。前移必须是可观察的规则事件。

### 阶段 D：击杀奖励与开局换牌

1. 非最后一名敌人阵亡且完整濒死结算结束后，进入 `KILL_REWARD` 流程。
2. 玩家选择回复 1 点体力或摸 2 张牌；AI 自动测试可通过固定策略选择。
3. 奖励结算完成后，再恢复原伤害/群体锦囊/回合 continuation。
4. 增加 `OPENING_MULLIGAN` 流程：仅战斗开始时一次，最多选择配置数量的手牌。
5. 换回的实体牌必须回到牌堆并洗牌，再等量摸牌；全场牌数必须守恒。
6. 玩家取消换牌时直接开始首回合，不能卡在中间状态。

击杀奖励不得在最后一名敌人死亡、玩家已死亡或战斗已经结束时触发。

### 阶段 E：UI 与信息表达

- 敌人面板显示“前排/后排”“精英/随从”、体力、手牌数、技能和阵亡状态。
- 需要选择目标时，距离不足的后排仍可见，但显示不可选原因，例如“距离 2，当前攻击范围 1”。
- 玩家区域显示当前“孤军”效果：本回合摸牌数和【杀】额度。
- 前排阵亡、后排前移时播放简短位移动画或至少显示明确日志与高亮。
- 战利品使用独立的二选一面板，显示回复后的实际体力与摸牌数量。
- 换牌面板显示“已选择 0/2”，支持选择、取消和确认。
- 第一轮敌方意图可先实现五类图标和文字，不要求展示具体暗牌。

### 阶段 F：敌方意图与威胁预算

此阶段在序章平衡稳定后进入：

1. 为 AI 行为打上攻击、控制、防御、治疗、蓄力标签。
2. 回合开始前根据手牌、距离、目标和技能生成主要意图。
3. AI 实际行动若因玩家响应或牌局状态变化无法执行原意图，可降级到同类合法行为，并在日志中说明。
4. 为 1v3 以上遭遇加入敌军共享威胁点；【杀】、伤害锦囊、强控制和爆发技能分别消耗配置化点数。
5. 不消耗威胁点的敌人仍可执行装备、治疗、弃牌和非进攻准备，保证其回合不是无意义跳过。

## 7. 预计代码影响范围

### 核心规则

- `scripts/GameManager.gd`
  - 扩展战斗配置。
  - 起手牌、摸牌、出【杀】额度查询。
  - 阵位距离和前移。
  - 击杀奖励、换牌及 continuation。
  - 平衡统计事件和日志。
- `scripts/Player.gd`
  - 增加本场阵位、敌人模板/单位类别等明确状态；在重新开始时正确清理。
- `scripts/skills/DrawContext.gd`
  - 如现有摸牌修正均通过上下文处理，则“孤军”应作为关卡规则修正接入，避免绕开武将技能。

- `scripts/UIManager.gd`
  - 阵位、补偿状态、换牌和战利品面板。

### 测试与文档

  - `tests/OneVsManyBalanceRuleTest.gd/.tscn`

## 8. 必须覆盖的验收用例

### 配置与开局

1. 第一战仍创建一名标准敌人，不获得“孤军”、体力加成、换牌和战利品。
2. 第二战创建一名前排精英和一名后排随从。
3. 玩家最大及当前体力只在本场增加 1，重新选将或退出战斗后不污染武将基础数据。
4. 玩家/精英/随从分别获得 4/4/2 张起始手牌，全场牌数守恒。
5. 换牌最多选择 2 张，取消、确认、无选择确认均能进入首回合。

### 距离与目标

6. 无装备时玩家可以【杀】前排，不能【杀】距离 2 的后排。
7. 合法武器、-1 坐骑或距离技能可以使后排成为目标。
8. 后排同样受其武器范围和坐骑修正，AI 不得绕过距离攻击玩家。
9. 前排阵亡后后排前移，之后双方距离变为 1。
10. 群体锦囊仍依次结算全部合法存活角色，不受前后排单体攻击距离限制误伤。

### 敌众补偿

11. 两敌存活时玩家正常摸牌阶段摸 3 张。
12. 玩家可合法使用两次【杀】，第三次被拒绝；装备和武将对次数的修正仍正确叠加。
13. 一名敌人阵亡后，玩家下一摸牌阶段恢复摸 2 张，出【杀】额度恢复标准值。
14. 跳过摸牌阶段时不得凭空获得“孤军”额外牌。

### 击杀奖励与流程恢复

15. 敌人阵亡后玩家可选择回复 1 或摸 2，不能两项都得。
16. 满体力时仍可选择回复，但实际不超过上限；UI 应提示实际收益为 0，便于玩家改选摸牌。
17. 最后一名敌人阵亡时直接胜利，不弹出战利品。
18. 群体伤害连续击杀多名敌人时，胜负、奖励与后续目标结算不重复、不丢失 continuation。
19. 玩家与首名敌人同时进入濒死链时，以完整伤害和濒死规则结算，不提前发放奖励。

### 回归与稳定性

20. 全部现有卡牌、技能、装备、判定和濒死测试继续通过。
21. 新增流程中不存在悬挂 AI 定时器、重复提交和永久停留状态。
22. 摸牌堆、弃牌堆、处理区、手牌、装备区、判定区和换回牌合计始终等于开局牌数。

## 9. 平衡测试计划

### 9.1 自动测试用途

自动 AI 对战主要验证：

- 战斗可以稳定结束。
- 阵位和距离合法性一致。
- 技能/卡牌组合不会令流程卡死。
- 卡牌总数守恒。
- 不同随机种子下没有异常极端长度。

自动 AI 胜率不能直接等同于真人玩家体验，但应统计玩家阵营胜率，作为发现异常组合的筛选器。

### 9.2 真人测试样本

首轮至少安排：

- 5 名了解三国杀规则的玩家，每人 5 局。
- 5 名只完成基础教学的玩家，每人 5 局。
- 覆盖至少 5 名不同玩家武将，并固定记录敌方组合。

测试后收集：

- 是否能在第一回合理解前后排与攻击距离。
- 首次失败原因是否清楚。
- 战利品选择是否形成有意义的续航/资源抉择。
- 玩家是否认为击杀第一名敌人后压力明显下降。
- 是否出现“连续数回合只能挨打”或“击杀首敌后必胜且无决策”的体验。

### 9.3 首轮目标

- 序章第二战首次通关率：70%~85%。
- 失败一次后的再次通关率：高于 85%。
- 成功局首名敌人击杀时间：通常为玩家第 3~4 个回合。
- 玩家无合法进攻行动的回合占比：低于 15%。
- 玩家武将之间胜率极差：不超过 20 个百分点。
- 无卡牌数量漂移、状态机死锁或测试看门狗持续救援。

## 10. 调参顺序

当首轮通关率过低时，按以下顺序调整：

1. 检查后排是否在攻击范围不足时仍通过 AI 特例发动攻击。
2. 移除敌方双控制、双爆发或强联动组合。
3. 将随从起始手牌从 2 降为 1，或体力从 3 降为 2。
4. 调整敌方威胁行为优先级和意图公开程度。
5. 最后才考虑提高玩家起手资源或体力。

当通关率过高时，按相反方向优先提高敌人行为质量、随从模板或阵容协同，不先移除阵型与信息提示。避免通过让敌人获得不可见伤害加成制造难度。

## 11. 推荐交付顺序

建议拆成三个可独立验收的开发批次：

1. **规则批次**：战斗配置、随从模板、玩家敌众补偿、确定性单元测试。
2. **阵型批次**：前后排距离、阵亡前移、目标 UI、距离与全卡牌回归测试。
3. **体验批次**：换牌、战利品、意图提示、平衡日志、真人测试和首轮调参。

每个批次都必须先通过现有规则与技能回归测试，再运行新增测试。不得等全部功能完成后才首次验证 1v1 是否被破坏。

## 12. 完成定义

满足以下条件后，才认为“序章 1v2 平衡改造”完成：

- 序章第一战、第二战和进入村落流程均可正常完成。
- 第二战的阵型、补偿、换牌和击杀奖励均有清楚 UI 与日志反馈。
- 玩家和 AI 共用卡牌、距离、技能、伤害和目标合法性入口。
- 全部既有回归测试和新增 1vN 测试通过。
- 完成至少一轮真人测试，报告玩家侧胜率及关键节奏指标。
- 首轮数据不达标时已经按本文件的调参顺序完成至少一次迭代，而不是只声明功能可运行。
