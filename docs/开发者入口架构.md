# 开发者入口架构

## 目标

开发者入口用于可复现地启动所有已注册战斗，不修改正常玩家的章节解锁规则。当前集中支持：

- 通过稳定战斗 ID 选择任意章节、事件或 BOSS 战；
- 根据战斗定义动态生成任意数量的敌方选将槽位；
- 指定玩家与全部敌方武将，并支持战斗自行决定是否允许重复武将；
- 决定停留在选将界面，或跳过选将直接开局；
- 从地图 UI 或命令行生成同一种启动配置。

## 职责边界

- `BattleCatalog`（Autoload）：注册、校验和查询全部战斗定义，是关卡元数据的唯一事实来源。
- `BattleSession`（Autoload）：保存当前稳定战斗 ID、提供当前定义，并广播与章节解耦的战斗结果。
- `DeveloperLauncher`（Autoload）：解析、校验、保存和一次性传递开发启动配置。
- `DeveloperPanel`：读取目录并动态创建 N 个敌方槽位，只收集 UI 输入。
- `MapScene`：显示调试入口，并在存在待处理配置时切换到战斗场景。
- `Main`：作为组合根消费配置、上报战斗结果，并按战斗定义路由返回场景。
- `GameManager`：提供与开发工具无关的 `setup_all_generals()` 和 `prepare_match_with_generals()`，负责合法、确定性地建立阵容。
- `PrologueState`：只维护序章线性进度并监听结果信号；`active_battle` 整数属性仅作为旧代码兼容层。

调用链：

```text
BattleCatalog.register_battle
        ↓
DeveloperPanel / CLI
        ↓
DeveloperLauncher.request_launch
        ↓
BattleSession → MapScene → Main
        ↓
GameManager.prepare_match_with_generals
        ↓
选将界面复核 或 start_match
        ↓
BattleSession.battle_completed → 章节进度监听器
```

## 生命周期约束

1. 启动配置是一次性的：`Main` 调用 `consume_launch_configuration()` 后，配置不再触发第二次场景跳转。
2. 最近一次有效配置会保留，用于再次打开面板时恢复选择。
3. 开发测试胜利后按定义的 `return_scene` 返回；失败是否重试由 `retry_on_loss` 决定。
4. 开发者 UI 和启动能力仅在调试构建启用，正式构建不接受开发启动请求。
5. 未指定的敌方槽位由 `GameManager` 按武将定义顺序确定性补齐，不使用随机结果。
6. 章节进度通过监听 `BattleSession.battle_completed` 更新，不允许 `Main` 依赖具体章节状态。
7. 开发选将和实际敌方展示均使用滚动容器，敌人数不再决定场景结构。

## 战斗定义模式

每个定义至少包含 `id`、`display_name` 和 `enemy_count`。推荐完整字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 永久稳定且全局唯一的 `StringName`，存档与命令行只引用此值 |
| `display_name` | 开发面板和日志名称 |
| `chapter_id` | 所属章节；对应进度对象通过它筛选结果 |
| `chapter_battle_index` | 章节内部顺序，可选 |
| `enemy_count` | 敌方角色数量，无固定上限 |
| `enemy_slots` | 可选槽位数组，支持 `label` 与 `default_general_id` |
| `combat_modifiers` | 关卡规则修正列表 |
| `kill_reward` | 击杀奖励策略 ID |
| `allow_duplicate_generals` | 是否允许阵容重复武将，默认 `false` |
| `developer_enabled` | 是否出现在开发面板，默认 `true` |
| `return_scene` / `failure_scene` | 胜利或非重试失败后的返回场景 |
| `retry_on_loss` | 失败后是否原阵容重开，默认 `true` |

例如注册一个 1v4 战斗，不需要修改开发面板、战斗场景或 `GameManager`：

```gdscript
BattleCatalog.register_battle({
    "id": &"chapter_1_swarm",
    "display_name": "第一章·伏兵",
    "chapter_id": &"chapter_1",
    "enemy_count": 4,
    "enemy_slots": [
        {"label": "前锋", "default_general_id": &"xuchu"},
        {"label": "左翼", "default_general_id": &"zhaoyun"},
        {"label": "右翼", "default_general_id": &"lvbu"},
        {"label": "后援", "default_general_id": &"diaochan"},
    ],
    "combat_modifiers": [],
    "return_scene": "res://scenes/ChapterOneMap.tscn",
    "retry_on_loss": true,
})
```

注册必须在开发面板或战斗入口首次查询目录之前完成；正式章节建议由章节 Autoload 在初始化时集中注册。

## 扩展约定

新增战斗只能通过 `BattleCatalog` 注册，不得再在 UI、卡牌或章节脚本中建立平行关卡配置。若未来增加卡组、初始体力、阵营、胜利条件或规则修正，先扩展目录定义与领域接口，再让 `Main` 负责适配；开发面板不得直接修改 `BattlePlayer` 或状态机字段。
